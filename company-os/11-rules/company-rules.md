# 公司规范 Company Rules

> Owner: Terry ｜ 适用：所有人、所有工作 ｜ 复审：每季度
> 背景见 [使命与价值观](../00-company/mission-vision-values.md)、[行为准则](../05-hr-teams/code-of-conduct.md)

## 1. 数据与保密

| # | 规范 |
|---|---|
| C-1.1 | **必须**把居民信息视为最高敏感级别。禁止把可识别居民的信息（姓名、房号、出生日期、病历号、照片）写进文档、聊天、邮件、工单、代码、提交信息或 AI 工具 |
| C-1.2 | 讨论具体案例时**必须**去标识化（"一位 80 多岁的女性居民"，而不是名字） |
| C-1.3 | **禁止**在个人设备上存储受限数据；只用公司管理的设备（MDM、全盘加密、MFA） |
| C-1.4 | **禁止**把受限或机密数据粘贴到未经批准的 AI 工具。已批准：在本仓库中使用 Claude Code 与 Codex 处理**公司文档和代码**（不含居民数据） |
| C-1.5 | 发现疑似泄露或丢失设备，**必须立即**报告 Terry（Privacy Officer 过渡期），不要先自行调查 —— 见 [数据泄露响应计划](../03-legal-compliance/data-breach-response-plan.md) |

## 2. 文档

| # | 规范 |
|---|---|
| C-2.1 | 公司事实的唯一来源是本仓库（`company-os/` 与 `docs/`）。口头约定不算数，写下来才算 |
| C-2.2 | 每份规范性文档头部**必须**有 Owner 与复审周期 |
| C-2.3 | 文件名用 kebab-case；日期用 `YYYY-MM-DD`；模块用两位编号前缀 |
| C-2.4 | 文档语言：中文正文 + 英文法律/行业术语；对外材料用英文 |
| C-2.5 | 移动或改名文件时**必须**保持相对链接有效 |
| C-2.6 | **禁止**修改 `company-os/08-feedback/raw/` 中的原始反馈（只能人工录入，录入后不改原话） |

## 3. 决策

| # | 规范 |
|---|---|
| C-3.1 | 难以逆转的决定（产品边界、数据处理方式、融资、签约、关键雇佣）**必须**写 DR —— 见 [决策机制](../02-operating-rhythm/decision-making.md) |
| C-3.2 | 涉及居民安全的发布，Clinical Lead 有否决权；Clinical Lead 到岗前，影响 AI 输出的发布**不得**标记为可发布 |
| C-3.3 | Terry 身兼 Product Owner 与 Tech Lead：生产与安全相关变更**必须**由至少一位其他开发者评审，不得自我批准 |
| C-3.4 | 讨论时充分反对，决定后全力执行（disagree and commit） |

## 4. 沟通

| # | 规范 |
|---|---|
| C-4.1 | 默认异步、默认书面；超过 3 段的讨论写成文档 |
| C-4.2 | 紧急事件（安全、数据、客户系统宕机）用电话 + 事件频道 |
| C-4.3 | 尊重 right to disconnect：非紧急事项不期望下班后回复 |
| C-4.4 | 对外（客户、媒体、社交平台）不讨论任何客户或居民的具体情况 |

## 5. 诚实与对外表述

| # | 规范 |
|---|---|
| C-5.1 | **禁止**夸大产品能力；对外数字必须有证据（Australian Consumer Law） |
| C-5.2 | **禁止**声称未取得的认证（如 ISO 27001）或"TGA 批准" |
| C-5.3 | 出了问题第一时间说清楚（open disclosure 精神） |

## 6. 使用 AI 助手（Claude、Codex）

| # | 规范 |
|---|---|
| C-6.1 | AI 助手遵守根目录 `AGENTS.md` 与本文件夹全部规范 |
| C-6.2 | AI 生成的内容由**人负责**：提交、发布、发送前必须由人审阅 |
| C-6.3 | AI 不对外发送任何东西（邮件、表单、监管通知）—— 只生成草稿 |
| C-6.4 | 法律合规内容由 AI 起草时标注"内部工作底稿，非法律意见" |
