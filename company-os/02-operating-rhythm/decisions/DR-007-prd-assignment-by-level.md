# DR-007: PRD 按难度与成员级别、方向分配

- **日期**：2026-10-11
- **决策人**：Terry
- **类型**：Type 2（双向门）—— 内部工作方式，可随时撤回
- **状态**：提议中
- **评论截止**：

## 背景
[DR-006](DR-006-prd-single-assignee.md) 规定每个 PRD 只有一个 Assignee，但没有规定该给谁。Terry 希望按成员特点分配：有人适合全栈，有人适合较简单的任务，按 Junior / Senior 和方向区分。`11-rules/AGENTS.md` 规定新增"必须/禁止"类条款须写 DR。

## 选项
| 选项 | 优点 | 缺点 |
|---|---|---|
| A. PRD 分 L1–L3 难度；成员在名册记录级别（Junior/Mid/Senior/Lead）与主方向；按"门槛 → 方向 → 负荷 → 轮换"选人，Terry 🛑 确认 | 高风险模块（归属、护栏、HITL、数据）只交给有经验的人；规则透明，可解释 | 需要 Terry 先为每人评定级别；难度判断有主观成分 |
| B. 只按方向分配，不分级别 | 简单 | 高风险 PRD 可能落到经验不足的人手里 |
| C. 每次由 Terry 凭判断指定 | 零规则成本 | 不透明，AI 无法给出有依据的建议，负荷容易不均 |

## 推荐与理由
选 A，细则见 [prd-assignment-rules.md](../../11-rules/prd-assignment-rules.md)。难度按 PRD 涉及的模块与临床风险判定，与 PRD C3 和各模块 `AGENTS.md` 的 hazard 一致；Junior 可经 Terry 同意、配导师承担 L2 成长任务，但不担任 L3。级别匹配不做自动检查，由 🛑 确认把关（KISS）。

**补充（2026-10-11，Terry）**：整份 PRD 归一人 —— PRD 的全部任务由 Assignee 负责并执行，不把同一 PRD 的任务拆给不同成员；评审人为另一人（规范 §3a）。一个人做不完时拆成多份 PRD。

## 影响检查
- [x] 居民安全 / 临床：正面 —— L3（改变 AI 输出、HITL、签字记录）须 Senior/Lead 负责并由他人评审
- [x] 隐私 / 合规：名册只记录级别与方向，不含薪酬或绩效评语；分配只看工作相关能力（反歧视，见规范 §6，未经律师核实）
- [x] 安全：无负面影响
- [x] TGA 判定是否改变：否
- [x] 成本 / 现金跑道：无

## 决定
待 Terry 确认。确认后：状态改为"已决定"，在 `decision-log.md` 追加 DR-007 一行；Terry 在团队名册填写每人的级别与主方向（同时解决名册"各 Developer 的分工方向"待决事项）。

## 复审
团队超过 4 人、招聘第一位外部 Senior，或运行一个季度后。
