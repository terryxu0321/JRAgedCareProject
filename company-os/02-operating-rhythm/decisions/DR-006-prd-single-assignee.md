# DR-006: 每个 PRD 有且仅有一个 Assignee

- **日期**：2026-10-11
- **决策人**：Terry
- **类型**：Type 2（双向门）—— 内部工作方式，可随时撤回
- **状态**：提议中
- **评论截止**：

## 背景
Terry 要求 PRD 能分配给团队成员，且每个 PRD 只有一个负责人。目前 `docs/PRD.md` 与 `company-os/06-app-development/specs/` 中的 spec 只写了 Owner（产品决策人），没有写由谁负责推进实现。`11-rules/AGENTS.md` 规定新增"必须/禁止"类条款须写 DR，故记录于此。

## 选项
| 选项 | 优点 | 缺点 |
|---|---|---|
| A. 在每份 PRD 头部写唯一一行 `Assignee`，`check_rules.py`（ASSIGN）自动校验，skill `assign-prd` 负责分配/改派 | 单一来源，无需同步；违反"仅一人"时检查失败 | 需要 PRD 作者遵守固定写法 |
| B. 另建一张 PRD 分配登记表 | 一眼看全 | 与 PRD 头部重复，容易不一致（违反 DRY） |
| C. 不做约束，口头分配 | 零成本 | 无记录，易出现多人或无人负责 |

## 推荐与理由
选 A。PRD 头部即唯一来源；"一览"由 skill 扫描生成，不另存。校验规则：最多一行 Assignee、只写一个名字、必须是 `05-hr-teams/team-roster.md` 名册成员 —— 否则 `ASSIGN` 失败；尚未分配只给 `WARN`，以免在负责人确定前阻塞其他检查。分配与改派都须 Terry 🛑 确认。

## 影响检查
- [x] 居民安全 / 临床：无影响（内部工作分配）
- [x] 隐私 / 合规：无影响（只记录成员名字，不含个人敏感信息）
- [x] 安全：无影响
- [x] TGA 判定是否改变：否
- [x] 成本 / 现金跑道：无

## 决定
待 Terry 确认。确认后：状态改为"已决定"，在 `decision-log.md` 追加 DR-006 一行；可再决定"未分配"是否从 WARN 升级为失败。

## 复审
团队超过 4 人，或出现需要多人共同负责的 PRD 时。
