## 1. 四个维度

养老机构里"买的人"、"用的人"、"受益的人"和"把关的人"往往不是同一个人。只打动其中一类，产品要么卖不出去，要么买了没人用。

| 维度 | 问题 | 在 CareKind 里意味着什么 |
|---|---|---|
| 💰 **谁买** Buyer | 谁批预算、签合同、决定续约？ | 按床位/月计价（[PRD A6](PRD.md#a6-商业模式假设待验证)），经济决策人看成本与风险；临床决策人看质量与员工负担 |
| 🎙️ **谁用** User | 谁每天打开 App、口述、审核草稿？ | 一线护理人员是记录的大多数作者；用不起来 = 试点失败 |
| 🌱 **谁受益** Beneficiary | 谁因为记录更好、更及时而获益？ | 居民与家属是最终受益人，但**不直接使用产品**；机构因审核就绪而受益 |
| 🛡️ **谁审核** Reviewer / Gatekeeper | 谁能否决或复核？ | 两层含义：① **记录复核**（RN 复核 PCW 草稿、签字责任）；② **采购把关**（IT/隐私、临床治理、质量合规审查） |

## 3. 10 个画像

每个画像统一结构：情境 → 目标 → 痛点 → 顾虑（会让 TA 说"不"的理由）→ 与产品的接触点 → 对 TA 说什么 / 不能说什么。

### P1 · 中小型养老机构 CEO / COO —— 经济决策人 💰

| 项 | 内容 |
|---|---|
| 情境 | 运营 1–10 个机构的中小型提供者（[ICP](../company-os/01-strategy/strategy.md)）；同时面对人手短缺、新 Aged Care Act 合规要求和资金压力；不懂临床细节，依赖 DON 的判断 |
| 目标 | 控制成本、降低合规与声誉风险、留住员工、通过质量审核 |
| 痛点 | 员工把大量时间花在补记录上（加班成本）；审核中记录相关发现带来整改压力；大机构能自建工具（如 Uniting 的 Buddy），自己做不到 |
| 顾虑 | 又一个系统、又一笔订阅费；数据出事谁负责；与现有护理系统重复录入；投资回报说不清 |
| 接触点 | Discovery 与 Demo 后期、试点成功标准评审、合同签署（[销售流程](../company-os/07-marketing-operations/sales-process.md)）|
| 对 TA 说 | 按床位计价、与现有护理系统并存而非替换、试点用北极星指标（每班记录耗时，[PRD G1](PRD.md#g1-成功度量试点)）说话 |
| 不能说 | 未经试点验证的省时百分比或 ROI 数字（ACL，见 [marketing-compliance](../company-os/07-marketing-operations/marketing-compliance.md)） |

### P2 · 护理总监 DON / Clinical Care Manager —— 冠军买家 💰🌱🛡️

| 项 | 内容 |
|---|---|
| 情境 | 对机构的临床质量与记录质量负总责；通常是 CareKind 的第一个联系人和内部推动者；配置模板与复核规则（[PRD C6](PRD.md#c6-权限与复核规则)） |
| 目标 | 记录准确及时（Outcome 2.7）、事件不遗漏、审核时拿得出记录、员工下班准时 |
| 痛点 | 记录质量参差，尤其英文写作吃力的员工；事件记录字段缺失；交接信息丢失；要花时间追着员工补记录 |
| 顾虑 | AI 写错进了档案谁负责；员工会不会不看就签字；会不会被认为是"AI 在做临床判断" |
| 接触点 | Discovery、Demo、上线配置（模板、复核规则、champion）、完整性看板、事件升级处理 |
| 对 TA 说 | 每句可溯源回听；不确定的不猜（待归属）；护士审核签字后才成为记录；模板映射法定字段 |
| 不能说 | "AI 识别风险/预警恶化/判断是否须上报 SIRS" —— 越过 TGA 边界（[PRD F1](PRD.md#f1-tga-判定)） |

### P3 · IT 与隐私负责人 —— 采购把关人 🛡️

| 项 | 内容 |
|---|---|
| 情境 | 中小机构里可能是兼职 IT、外包 MSP，或由运营经理兼任隐私官；负责安全问卷、DPA 审查、SSO 与设备管理 |
| 目标 | 不出数据泄露、满足 Privacy Act 与州法、部署简单、不增加运维负担 |
| 痛点 | 每个供应商都要从头审一遍；小供应商资料不全；健康信息出境与子处理方说不清 |
| 顾虑 | 数据是否在澳洲（含 AI 推理）；是否用客户数据训练模型；录音是否构成员工监控；供应商倒闭后数据怎么办 |
| 接触点 | Security & Privacy Review 阶段（2–6 周）、D1 上线配置（SSO、名册、同意状态、保留期） |
| 对 TA 说 | 信任包（Trust Pack）：澳洲驻留、不训练、不做生物识别、原音签字后短期删除、子处理方清单、审计日志 |
| 不能说 | 尚未完成的认证或 PIA 结论；未经律师确认的保留期结论（[PRD G4](PRD.md#g4-待决问题) #6） |

### P4 · 质量与风险经理 Quality & Risk Manager —— 内部审核人 🛡️🌱

| 项 | 内容 |
|---|---|
| 情境 | 较大的中小机构才有专职岗位，否则由 DON 兼任；负责内部审计、事件管理、SIRS 上报流程、迎接 Aged Care Quality and Safety Commission 审核 |
| 目标 | 记录"audit-ready"；事件记录字段齐全；SIRS 时限不超；能举证 7 年 |
| 痛点 | 审核前临时抽查补漏；事件记录缺法定字段；谁在什么时候改过记录说不清 |
| 顾虑 | AI 生成内容在审核中是否被认可；更正记录是否可追溯；会不会被用来监控员工绩效 |
| 接触点 | 完整性看板（只读或经授权）、事件快速通道、审计日志导出 |
| 对 TA 说 | 签字后只能追加更正不能覆盖；事件模板映射法定字段；SIRS 只做计时提醒，判断仍由人做 |
| 不能说 | "保证通过审核"；任何按员工个人排名的统计（[PRD A7](PRD.md#a7-我们不做什么) 不做员工绩效监控） |

### P5 · 多语言护理员 PCW / AIN（CALD 背景）—— 核心用户 🎙️🌱

| 项 | 内容 |
|---|---|
| 情境 | 照护工作熟练，英文口语可以，但英文书面记录慢、怕写错；常做早班或晚班，一个班负责十几位以上居民；下班前或下班后补记录 |
| 目标 | 记录又快又对；不因为英文写作被质疑专业能力；准时下班 |
| 痛点 | 记录时间长、要回忆一整班的细节；担心语法和用词不专业；手套、推车、被打断时无法打字 |
| 顾虑 | AI 是不是在监视自己；用母语说会不会被看不起；签了 AI 写的东西出错算谁的 |
| 接触点 | 开班确认负责名单 → 整班按键口述 → 班末逐位居民审核草稿 → 签字或提交 RN 复核（[PRD D2](PRD.md#d2-一个班次护理人员视角模式-a)、[D4](PRD.md#d4-pcw-起草--rn-复核)） |
| 对 TA 说 | 只管说，系统整理；母语输入、英文草稿、原文可对照；草稿要你看过才算数 |
| 不能说 | "AI 写的不用检查" —— HITL 是硬规则 |
| 设计要点 | 大按钮、单手操作、离开房间后口述的提示、清晰的"待归属"处理；界面文字简单（[DESIGN.md](../company-os/06-app-development/design-system/DESIGN.md)） |

### P6 · 资深本地护理员 PCW —— 采用阻力 🎙️

| 项 | 内容 |
|---|---|
| 情境 | 工作年限长、英文母语、熟悉现有纸质或系统流程；常是同事请教的对象，态度会影响整个班组 |
| 目标 | 别打乱已经熟练的流程；把时间留给照护居民 |
| 痛点 | 新系统一个接一个，培训多、用不久；现有系统录入步骤繁琐 |
| 顾虑 | 对着手机说话不自然；AI 写的不像自己的话；担心被录音监控；担心工作被替代 |
| 接触点 | 上线培训、第一周使用、班组内口碑 |
| 对 TA 说 | 不替代你的判断，只省掉打字；你可以改任何一句；只有你按键时才录音 |
| 不能说 | "必须用"式的强推话术；夸大省时效果 |
| 设计要点 | 第一次使用就能完成一条完整记录；可编辑、可退回手写；争取成为 champion 而不是反对者 |

### P7 · 班长注册护士 RN（Shift Lead）—— 用户兼复核人 🎙️🌱🛡️

| 项 | 内容 |
|---|---|
| 情境 | 一个班次里可能是唯一或少数 RN，负责全楼层；既写自己的临床记录，又复核 PCW/AIN 的记录，处理事件与交接；夜班常更紧张 |
| 目标 | 自己的记录快速完成；复核不成为新负担；交接信息完整；事件不遗漏 |
| 痛点 | 复核别人的记录要来回追问；交接靠记忆和纸条；事件记录压在班末 |
| 顾虑 | 复核 AI + PCW 生成的内容，责任落在自己的执业注册上（Ahpra/NMBA）；复核量太大反而更慢 |
| 接触点 | 自己口述与签字、PCW 记录复核队列、事件快速通道、交接摘要、完整性看板（[PRD C6](PRD.md#c6-权限与复核规则)） |
| 对 TA 说 | 每句话可回听原话；复核界面按居民聚合；签字留痕清楚标明谁写、谁复核 |
| 不能说 | "AI 已经核对过了，你可以快速签" —— 复核责任不能转移给 AI |
| 待决 | PCW 记录默认是否需 RN 复核（[PRD G4](PRD.md#g4-待决问题) #3） |

### P8 · 登记护士 EN —— 中间层用户 🎙️🌱

| 项 | 内容 |
|---|---|
| 情境 | 在 RN 监督下执业；有的机构让 EN 复核 PCW 记录，有的不让（[PRD C6](PRD.md#c6-权限与复核规则) "可配置"） |
| 目标 | 记录高效；角色边界清楚 |
| 痛点 | 复核权限因机构而异，流程不一致；同时承担照护与记录 |
| 顾虑 | 被要求复核超出自己执业范围的内容 |
| 接触点 | 口述、签字、（可配置的）复核队列 |
| 对 TA 说 | 你能做什么由机构配置决定，界面只显示你被授权的操作 |
| 设计要点 | 权限按角色和机构配置，界面不出现无权操作 |

### P9 · 居民（含认知障碍居民）—— 最终受益人 🌱

| 项 | 内容 |
|---|---|
| 情境 | 住在机构里的老人，部分有认知障碍；**不使用产品**，但记录写的是 TA 的生活与照护 |
| 目标 | 被准确、尊重地记录；偏好和生活习惯被照护者知道；隐私与尊严受保护 |
| 获益 | 照护者把时间还给照护；交接更完整；以人为本的时间线沉淀偏好（[PRD A3](PRD.md#a3-产品亮点highlights) #7） |
| 风险 | 记录进错档案（归属错误）；私人对话被录到；被贬低的措辞 |
| 权利 | 可以拒绝 AI 处理其记录；未同意居民的语句立即丢弃（[PRD C3](PRD.md#c3-归属引擎逻辑核心)） |
| 设计要点 | 只做按键口述（模式 A）；以人为本、尊重的记录语言；不做生物特征识别；任何功能都不为居民生成诊断或风险评分 |

### P10 · 家属 / 支持决策人 Supporter —— 间接受益人与同意参与者 🌱

| 项 | 内容 |
|---|---|
| 情境 | 关心亲人照护质量；部分是认知障碍居民的支持决策人，参与同意；**不登录产品** |
| 目标 | 知道亲人过得怎么样；信任机构；亲人的隐私被尊重 |
| 获益 | 机构与家属沟通时有更完整、更及时的记录依据（家属沟通草稿属 H2 方向，[PRD A4](PRD.md#a4-发展方向三个阶段)） |
| 顾虑 | "AI 在录我家人吗？"；数据是否出境；能否拒绝 |
| 接触点 | 机构的告知与同意流程（[PRD D8](PRD.md#d8-同意管理)）——CareKind 提供材料模板，由机构执行 |
| 设计要点 | 告知材料用通俗语言说明：录什么、不录什么、数据在哪、如何拒绝 |

## 4. 画像之间的关系

```
                 💰 谁买                              🛡️ 采购把关
        P1 CEO/COO  ◄── 推荐 ──  P2 DON  ──── 需要通过 ────►  P3 IT/隐私
           │ 签约                   │ 配置模板、复核规则           P4 质量与风险
           ▼                        ▼
      ┌───────────────── 🎙️ 谁用（每个班次）─────────────────┐
      │  P5 多语言 PCW ─┐                                    │
      │  P6 资深 PCW  ──┼─ 起草 ──►  P7 RN 复核签字 ◄── P8 EN（可配置）│
      └─────────────────┴──────────────────┬───────────────────┘
                                           ▼ 签字记录 → 机构护理系统
                 🌱 谁受益：P9 居民 ◄── 同意 / 支持决策 ── P10 家属
```

- **冠军是 P2，签字是 P1，否决可能来自 P3**：销售需要同时准备临床价值（P2）、成本与风险（P1）、信任包（P3）三套材料。
- **试点成败取决于 P5、P6、P7**：P5 是价值最大的用户，P6 决定班组口碑，P7 决定复核是否成为瓶颈。
- **P9、P10 不付费、不使用，但拥有拒绝权**：同意流程走不通，产品在该居民身上就不能用。

## 5. 对产品、销售与设计的含义

| 画像 | 产品优先 | 销售 / 上线 | 成功信号（对应 [PRD G1](PRD.md#g1-成功度量试点)） |
|---|---|---|---|
| P1 | 按床位计价、导出/回写不双录 | 试点结论用北极星指标汇报 | 试点转年度合同 |
| P2 | 模板配置、完整性看板、事件快速通道 | Discovery 第一联系人；指定 champion | 记录及时性、关键信息遗漏 = 0 |
| P3 | SSO、澳洲驻留、审计日志、保留期配置 | 信任包、DPA 提前准备 | 安全审查在计划时长内通过 |
| P4 | 签字不可覆盖、更正留痕、事件法定字段 | 审核场景演示 | 事件记录字段完整 |
| P5 | 多语言输入、原文对照、按键口述 | 母语培训材料 | 每班记录耗时下降、周活跃率 |
| P6 | 首次使用即成功、随时可改 | 让 P6 参与试点设计 | SUS ≥ 70、周活跃率 |
| P7 | 按居民聚合的复核队列、一键回听、交接摘要 | RN 培训强调复核责任与 AI 局限 | 复核不增加班末耗时 |
| P8 | 角色可配置的权限 | 机构配置时确认 EN 权限 | — |
| P9 | 归属"绝不猜测"、未同意即丢弃、尊重措辞 | — | 高置信误归属 = 0 |
| P10 | 通俗的告知材料模板 | 机构执行告知与同意 | 同意流程无投诉 |

**设计取舍提醒**：当画像之间冲突时，按这个顺序取舍 —— **P9 居民安全与权利 > P7 的复核责任 > P5/P6 的使用效率 > P1/P2 的管理需求**。例如：P2 想要更多"自动判断"，但只要触及诊断、风险评分或预警，一律不做（TGA 红线）。
