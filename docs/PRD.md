# Part A · 战略分析：方向、亮点与突破

## A1. 我们从调研中看到了什么

| 发现 | 含义 |
|---|---|
| **"会转写"已不稀缺**：Heidi、Lyrebird 等通用 scribe 和 AlayaCare、ShiftCare 等系统内置 AI 都能把语音变成 note | 不能靠"AI 记录"本身取胜 |
| **最大威胁是 Heidi Health**：2026-09 融资 US$340M，已推出 aged care 方案（护理记录、事件报告、母语输入→英文、挂绳录音器），新西兰 Metlifecare 从 1 家扩到 4 家 | 必须在 Heidi 没做好的地方赢 |
| **Heidi 的空白**：未公开与任何澳洲养老系统集成；面向 RN/临床医生，而非 PCW | 我们的切入口 |
| **澳洲机构养老系统**（Telstra Health、Leecare、AutumnCare、PCS、eCase）**尚无生成式 AI 记录**；海外同类（PointClickCare、Access、Birdie）已内置 | 窗口期约 12–24 个月（推测）；之后系统厂商可能自带 |
| **居家养老（Support at Home）已拥挤**：AI 已捆绑在 A$8–25/用户/月的套餐里 | 第一阶段不进入 |
| **多语言护理员需求已被验证**：Uniting NSW.ACT 自建 "Buddy"，1,200+ 员工，记录时间 15 分钟 → <2 分钟 | 需求真实；中小机构无力自建 → 我们的 ICP |
| **记录质量是法定义务**：Outcome 2.7（准确且及时）、事件记录 13 项法定字段（Rules s164-25）、SIRS 24 小时/30 天、7 年保留 | 合规可以做成产品结构，而不只是承诺 |
| **TGA 执法收紧**：只整理不解读的 scribe 不是医疗器械；2026-08 起重点查"功能越界" | documentation-only 是护城河也是红线 |
| **录音同意**：NSW、WA、SA、TAS、ACT 一般需全体当事人同意，违反为刑事犯罪 | 按键口述是唯一可快速规模化的模式 |

## A2. 核心洞察（产品突破口）

> **通用 AI scribe 的设计单位是"一次问诊 = 一位病人"。养老护理的真实工作单位是"一个班次 = 一位护理员 × 十几到几十位老人"。**

- GP scribe：开始问诊 → 录音 → 结束 → 一份 note。病人身份在开始前就确定了
- 养老护理员：8 小时里在走廊、房间、餐厅之间穿梭，几十次零碎观察，**涉及谁是在说话时才出现的**
- 现有工具要求护士每次先选老人再录音 —— 在戴手套、推车、被打断的现实中，这一步就是摩擦来源

**CareKind 的突破：以"班次"为单位，护士只管说，系统负责"这句话属于哪位老人"。** 这是 aged care 专属的问题，通用 scribe 的架构不会自然长出这个能力。

## A3. 产品亮点（Highlights）

| # | 亮点 | 为什么重要 | 对手情况 |
|---|---|---|---|
| 1 | **一个班次，零打字**：全班随口记录 → 自动按老人整理成草稿 | 护士下班不再补记录 | scribe 按"单次问诊"设计 |
| 2 | **智能归属，绝不猜测**：只在高置信时自动归属；不确定就放进"待归属" | 记录进错老人档案是最严重的风险之一 | 未见同类能力 |
| 3 | **为 PCW 和多语言护理员而生**：母语口述 → 专业英文记录，原文可对照；PCW 起草 → RN 复核签字 | 护理员才是记录的大多数作者 | Heidi 面向 RN；Buddy 只服务自家机构 |
| 4 | **合规即结构**：模板直接映射法定字段（事件 13 项、限制性措施、交接），SIRS 时限提醒，完整审计留痕 | 让每条记录都"审核就绪（audit-ready）" | 多为通用 note 格式 |
| 5 | **每句话可溯源**：草稿中每句都能一键回听原话 | 建立护士与 DON 的信任；防幻觉 | 少见 |
| 6 | **写回现有系统**：做现有护理系统的 AI 记录层，不替换 | 机构不用换系统、不用双录 | Heidi 未展示澳洲集成 |
| 7 | **以人为本的老人时间线**：从日常记录中沉淀每位老人的偏好与生活信息（来源可追溯） | 支撑 Standard 1（以人为本） | 少见 |
| 8 | **隐私是设计，不是条款**：按键口述、澳洲驻留、不训练、不做生物识别、原音短期删除 | 机构 IT/隐私审查更快通过 | 部分对手有澳洲托管声明 |

## A5. 定位

> **For** 澳洲中小型机构养老提供者的护理员与护士，
> **who** 每个班次都要为几十位老人补写记录，
> **CareKind AI** 是一款以班次为单位的 AI 记录助手，
> **that** 让护理员随口说、自动按老人整理成合规记录，并写回现有护理系统。
> **Unlike** 为医生问诊设计的通用 AI scribe，
> **we** 为护理员和养老工作流而生：多语言、按老人自动归属、护士始终做主。

对外一句话（只讲自己、可核实，不评价对手 —— 符合 ACL）：*"CareKind 以班次为单位、为护理员（包括 PCW）设计，自动按老人整理记录，并直接写回你现有的护理系统。"*

> 内部理解（不对外使用）：Heidi 已有 aged care 方案，但以 RN/临床人员为中心，且未公开澳洲护理系统集成 —— 这是我们要赢的地方。

# Part B · 产品定义

## B1. 一句话

护士和护理员在整个班次中随时用语音记下观察，**CareKind AI 自动识别每段话说的是哪位老人**，整理成各自的护理记录草稿；护士按老人逐一审核签字，记录进入每位老人的时间线，并导出或回写到机构护理系统。

## B2. 用户与角色

| 角色 | 需求 | 在产品中做什么 |
|---|---|---|
| **PCW / AIN（护理员）** | 不打字、不怕英文写作、下班准时 | 口述日常护理（ADL、饮食饮水、如厕、睡眠、情绪），审核自己的草稿；按机构政策提交 RN 复核 |
| **RN / EN** | 快速完成记录与复核；事件不遗漏 | 口述、审核、签字；复核 PCW 记录；处理事件草稿 |
| **DON / Clinical Care Manager** | 记录质量、审核就绪、事件及时 | 配置模板与复核规则；看完整性看板；处理事件升级 |
| **公司管理员（养老公司老板 / 运营负责人）—— 买单者** | 一处管理旗下多家、多地点养老院；看各院记录工作是否跟得上 | 跨院总览、新增养老院、任命院长、公司级流程默认值；可进入任一院管理（机构管理端，[SPEC-011](../company-os/06-app-development/specs/2026-10-provider-admin-console.md)） |
| **院长 / 机构管理员 / IT** | 安全、隐私、易部署 | 本院员工名册（含非 App 员工与资质到期）、老人名册与生命周期、同意状态、审核与上报流程、上线清单、审计（机构管理端） |
| **CareKind 平台管理员（Super Admin）** | 开通和配置客户公司 | 公司（租户）开通/停用、功能配置、公司管理员账号、去标识用量（Super Admin App）；**不接触居民健康信息** |
| **居民 / 家属**（间接） | 隐私、尊严、知情 | 通过机构的同意流程知情；可拒绝 AI 处理 |

按"谁买、谁用、谁受益、谁审核"展开的 10 个用户画像见 [user-personas.md](user-personas.md)（假设，待访谈验证）。

## B3. 核心概念

| 概念 | 定义 |
|---|---|
| **公司 Organisation** | 客户（养老公司），即一个租户；下设一家或多家养老院，可跨州 |
| **养老院 Facility** | 公司旗下的一个地点；有所在州、床位；员工、老人、流程配置都按养老院划分。员工属于公司，可分配到多家院 |
| **班次会话 Shift Session** | 一位护理人员从开班到下班的工作单元；本班所有语音片段归入其中 |
| **负责名单 Assigned Residents** | 开班时确认的本班负责老人（来自机构名册）；是归属的首要候选范围 |
| **语音片段 Voice Note** | 护理人员**主动**按键录下的一段话（通常 5 秒–3 分钟） |
| **转写 Transcript** | 片段的文字；带词级时间戳与置信度 |
| **语句 Utterance** | 转写拆分后的最小语义单元（通常一句），是归属与溯源的单位 |
| **归属 Attribution** | 语句 → 老人的关联，带置信度和依据 |
| **记录草稿 Draft Record** | 按记录类型与机构模板生成的单条记录；每句链接到来源语句 |
| **签字记录 Signed Record** | 护理人员审核确认后的正式记录（身份 + 时间戳）；之后只能追加更正，不能覆盖 |
| **老人时间线 Resident Timeline** | 某位老人所有已签字记录的时间序列视图 |
| **同意状态 Consent Status** | 机构维护的"该老人是否同意 AI 处理其记录"；未同意的老人不经 AI 处理 |

## B4. 录音模式决策

用户目标是"一个班次约 8 小时的录音自动分配给每位老人"。实现方式决定合规风险：

| 模式 | 怎么录 | 录到谁 | 合规 | 结论 |
|---|---|---|---|---|
| **A. 班次语音日志** | 护理人员整班随时**按键录一段**，说完松开；片段自动汇总 | 主要是护理人员本人对设备口述 | 符合 DR-004"按键口述"默认；Ahpra 要求的"首步明确同意"可在机构层落实 | ✅ **MVP 采用** |
| B. 佩戴式连续录音 | 麦克风整班开启 | 护理人员 + 在场的老人、同事、访客 | 录到私人对话 → 需全体同意 | ❌ 风险同 C，价值不高于 A |
| **C. 环境全程录音** | 房间内/整班持续录音，从对话中提取 | 所有在场者 | NSW、WA、SA、TAS、ACT 一般需全体当事人同意，违反为刑事犯罪；认知障碍老人需支持决策人；员工另有 Workplace Surveillance 通知要求 | ⏸️ 不进入 MVP；需 **DR-006** + 律师逐州书面意见 |

**模式 A 如何实现"8 小时自动分配"**：护理人员不需要每次先选老人 —— 只要在话里自然提到（"12 号房 Mary 早餐吃了一半，拒绝喝水"），系统就会自动归属。班末看到的是按老人整理好的草稿，而不是 8 小时的录音。

**UI 提示**：建议在离开老人房间后口述；避免在老人与他人私人对话时录音。

## C2. AI 管线逻辑（每个片段）

| 步骤 | 输入 → 输出 | 关键逻辑 | 失败时 |
|---|---|---|---|
| ① 转写 | 原音 → 转写 + 词级置信度 | 名册姓名/常用名/房号作热词；药品与护理术语表；多语言自动识别 | 低置信词标"[请确认]"；整段失败 → 提示重录，保留原音 |
| ② 拆分 | 转写 → 语句列表 | 按句与话题切换拆分；保留每句的时间区间 | 无法拆分 → 整段作为一个语句 |
| ③ 归属 | 语句 → 老人 + 置信度 + 依据 | 见 C3 | 中/低置信 → "待归属" |
| ④ 分类 | 语句 → 记录类型 | progress note / ADL 子项 / 行为观察 / 伤口描述 / 生命体征（陈述）/ 家属沟通 / **事件** | 不确定 → 归为 progress note |
| ⑤ 抽取 | 语句 → 模板字段 | 只抽取明确说出的值（如"喝了 200 毫升"）；未说的字段留空 | 留空，不推断 |
| ⑥ 起草 | 语句 + 字段 → 草稿 | 机构模板与以人为本的措辞；**只写说过的内容**；同一老人同类内容合并 | 生成失败 → 显示原始转写供手动编辑 |
| ⑦ 校验 | 草稿 → 通过/标记 | **忠实性核对**：每句草稿须能对应到来源语句，否则删除并标记；**禁止内容过滤**：诊断/治疗/用药建议/风险判断 → 阻止并记录；药名、剂量、数字、事件 → 标为关键项 | 校验不通过的句子不进入草稿 |

## C3. 归属引擎逻辑（核心）

```
                     语句
                       │
          ┌────────────▼────────────┐
          │ 候选生成                │  在本机构名册中匹配：全名、常用名、
          │（优先本班负责名单）      │  姓、房号/床号、读音近似（同音、口音）
          └────────────┬────────────┘
                       │
          ┌────────────▼────────────┐
          │ 证据打分                │  + 姓名与房号一致         + 在本班负责名单内
          │                         │  + 名册中唯一匹配         − 同名/近似名存在
          │                         │  − 只有代词（她/他）      − 转写置信度低
          └────────────┬────────────┘
                       │
        ┌──────────────┼──────────────────────┐
        ▼              ▼                      ▼
   高置信           中置信                  低置信 / 无候选 / 多候选
   自动归属         建议归属（需确认）       进入"待归属"
   显示依据         显示依据 + 候选           由护理人员手动选择
```

**硬规则**：
1. **高置信**须同时满足：唯一候选 **且**（两个标识一致，如姓名+房号；或名册中唯一的姓名且在本班负责名单内）
2. 代词指代（"她还说膝盖疼"）**最多**为中置信，即使上一句已归属
3. 同名居民存在时，仅凭姓名**永远不是**高置信
4. 不使用声纹、人脸等生物特征
5. 未同意 AI 处理的老人：识别归属必须先转写，因此——语句一旦被识别为涉及未同意老人，**立即丢弃**该语句的转写文本与对应原音片段，不生成草稿，只提示"有一段内容涉及未同意 AI 处理的老人，请手动记录"。同意的范围在 DPA 与告知材料中如实说明（律师确认措辞）
6. 审核界面始终显示**第二标识**（照片或房号），供人确认（对应 H-03/H-09）

## C4. 记录状态机

```
 已采集 ──► 已转写 ──► 已归属 ─────────────► 草稿 ──► 审核中 ──► 已签字 ──► [需复核?] ──► 已复核 ──► 已导出/已回写
 Captured   Transcribed  (自动/已确认)       Draft    In review   Signed      是 → RN 复核    Co-signed   Exported
                  │            │                         │           │
                  │            └─► 待归属 ──(手动指定)──┘           └─► 更正：新建版本，原版本保留（只追加）
                  └─► 转写失败 → 提示重录                  └─► 护理人员删除（留审计记录）
```

- **签字前**：草稿可编辑、改归属、拆分、合并、删除
- **签字后**：不可覆盖；更正 = 新版本 + 原因 + 签字（满足审计与 7 年举证）
- **原音**：签字后按保留策略删除（默认 ≤ 7 天，可配置）；删除操作写入审计日志

## C5. 事件快速通道

- 分类为**事件**（跌倒、皮肤破损、用药差错、行为事件、走失等）的语句：
  1. 立即生成**事件草稿**，按 Rules s164-25 的事件记录要素生成字段
  2. **立即**推送提醒该护理人员（及按配置的值班 RN）审核，不等班末
  3. 缺失字段以"未记录：……"提示 —— 只提示**记录字段**，不提示临床结论
  4. 显示提示："这可能需要按机构流程判断是否属于须上报事件（SIRS）"，并显示自观察时间起的计时 —— **只提醒，不判定**
- 是否上报、上报内容，由机构人员决定并在其系统中完成

# Part D · 工作流 Workflows

## D1. 机构上线（一次性）

```
签约(MSA+DPA) → 安全/隐私审查(信任包) → 管理员配置
                                          ├─ SSO / 用户与角色
                                          ├─ 居民名册导入（姓名、常用名、房号、可选照片）
                                          ├─ 同意状态（机构完成告知与同意后录入）
                                          ├─ 模板与复核规则（DON）
                                          ├─ 保留期
                                          └─ 记录转入机构系统的约定（天数、负责人）
→ 机构按 NSW Workplace Surveillance Act 等向员工发出书面通知（CareKind 提供模板；NSW 要求提前 14 天）
→ 分角色培训（强调审核责任与 AI 局限） → 指定 champion → 基线计时 → 上线
```

## D2. 一个班次（护理人员视角，模式 A）

```
开班
 1. 登录（SSO 或共享设备快速登录）
 2. 确认本班负责老人（名册预填，可调整）
班次中（重复数十次）
 3. 离开房间后按键："8 号房 John 午饭全吃完了，喝了一杯茶，下午睡了两小时" → 松开
 4. 后台自动：转写 → 拆分 → 归属 → 起草；App 角标显示"待审核 N"
 5. 若是事件 → 立即提醒审核（见 D3）
 6. 无网络时照常录音，联网后自动上传
班末（或任何空档）
 7. 打开"待审核"：按老人分组
 8. 先处理"待归属"（手动指定老人）
 9. 逐位老人：看草稿 → 必要时回听/编辑 → 关键项逐项确认 → 签字
10. 下班前提醒：未审核 0 条才算完成
11. 生成交接摘要（基于已签字记录）
```

## D3. 事件快速通道

```
护理人员口述"Mary 在浴室滑倒，右手腕擦伤，已扶回床上，通知了 RN"
 → 分类：事件 → 生成事件草稿（法定要素字段）
 → 立即推送：护理人员 +（配置的）值班 RN
 → 草稿显示：已记录字段 / 未记录字段 / 自观察起计时 / "按机构流程判断是否须上报"
 → 护理人员补充、签字 →（需要时）RN 复核
 → 导出/回写到机构事件系统；上报与否由机构人员决定
```

## D4. PCW 起草 → RN 复核

```
PCW 签字（"提交复核"） → RN 的"待复核"队列（按老人）
 → RN 查看草稿、原文、原音、PCW 的修改
 → 通过 → 已复核 → 导出/回写
 → 退回（附意见） → PCW 修改后重新提交
```

## D5. 交接（Handover）

```
班末 → 系统汇总本班"已签字"记录（按老人）
 → 置顶：事件、跌倒、拒食拒水、行为变化、未完成事项（只来自记录，不做判断）
 → 接班护士查看；口头交接仍按机构流程进行（ISBAR 等）
```

## D6. 老人时间线

```
已签字记录 → 按时间进入时间线 → 可按类型筛选
护理人员提到的偏好（"喜欢早上喝茶"） → 标记为"个人偏好"（来源可追溯） → 时间线顶部汇总
记录型数据（饮水量、进食比例） → 表格/曲线展示 —— 不做"偏低/异常"判断，不预警
页面标注："机构护理系统为正式记录库"
```

## D7. 导出与回写

```
MVP：复制到剪贴板 / PDF（含签字人、时间、版本）
H2：集成适配器 → 写入机构护理系统对应老人与记录类型 → 回写结果回执 → 失败重试与告警
```

## D8. 同意管理

```
机构完成居民/支持决策人告知与同意（CareKind 提供多语言告知模板）
 → 管理员在后台设置每位老人的同意状态
 → 未同意：该老人的语句不经 AI 处理，提示手动记录
 → 撤回同意：立即生效；历史签字记录按合同处理
```

## D9. 异常与失败

| 情况 | 系统行为 |
|---|---|
| 无网络 | 本地加密缓存，联网后上传；显示"待上传 N" |
| 转写失败 | 提示重录，保留原音 |
| 生成失败 | 显示原始转写，可手动编辑签字 |
| 服务中断 | 明确提示；机构启用手工记录备用流程 |
| 设备丢失 | 远程注销与擦除；本地缓存加密 |
